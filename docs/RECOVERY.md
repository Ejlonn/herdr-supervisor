# Restart and machine recovery

Durable supervisor state records the active run, accepted delivery, current turn, native session identity, gates, quota waits, and pending notifications. Restart reconciliation never auto-continues `WAIT_USER`, `PAUSED`, or `CANCELLED`, never guesses from aliases, and never replays an uncertain prompt.

A prompt is submitted exactly once. When the installed Herdr CLI supports it (`herdr agent prompt --wait --until working --until blocked`, present since Herdr 0.9), delivery is acknowledged the moment Herdr observes the agent start working or hit a dialog after submission, and the lifecycle monitor begins immediately (`prompt ack: lifecycle` in `herdr-supervisor doctor`; bound `prompt_ack_timeout_ms`, default 8000, above Herdr's own 5-second stall report). Older CLIs keep the settlement wait (`prompt ack: settle`), which costs up to `prompt_wait_timeout_ms` (default 20 s) before monitoring starts. In both modes a stalled or timed-out submission is recorded as uncertain: an observed working agent confirms it, an idle agent without a matching block stops in `WAIT_USER`, and nothing is ever resent.

On a replacement machine:

1. Install Herdr and this package without starting services.
2. Restore repositories from their configured Git remotes into new directories.
3. Restore a chosen verified filesystem snapshot into a new directory.
4. Inspect manifests, checksums, HEADs, branch/dirty metadata, and exclusions.
5. Reauthenticate Telegram, Claude, Codex, SSH, and other services whose credentials were excluded.
6. Configure new paths and run read-only doctor checks.
7. Restore native agent sessions only when their durable identities can be verified.
8. Activate services individually after checking for conflicts.

Never restore over a live workspace automatically and never infer task completion from a Herdr lifecycle label alone.

Routing results are read as logical protocol fields, not terminal rows: a value that the terminal hard-wrapped (a long payload path, a handoff) is reconstructed only inside an expected ordered eight-key frame, bounded by each value's validated size, and every run/turn, enum, placeholder, payload-root, duplicate, conflict, and length rule then applies to the reconstructed values. The emitted contract joins handoff words with underscores and forbids spaces, so a terminal can only split a handoff on full rows and concatenation reproduces it exactly (every status, Telegram, and completion surface displays a contract handoff exactly as emitted, underscores included); a legacy spaced handoff is re-joined best-effort and capped at a few rows. Text outside a frame is never merged into a value. If a settled accepted turn still has no result, the supervisor records a bounded `missing_result` descriptor and waits; the Telegram `Retry routing result` action or a `retry_routing_result` inbox command rereads that exact turn **once**: a recovered human gate is created normally, a recovered provider handoff is recorded and left for an explicit `/resume` (the retry never delivers a prompt), and a failed reread is spent — Ask agent, revision, or cancel remain.

A gate-preserving follow-up (`ask_agent`) is its own durable record (`agent_followup`): the suspended decision (gate id and hashes, or the unread turn and its retry count, plus the wait fields and the workflow delivery record) is persisted before the follow-up prompt is prepared, and restoration is derived from that descriptor alone. Restart recovery resumes the existing follow-up with its own turn and delivery identity: a `PREPARED` record without a delivery is delivered once; a `prepared`/`accepted`/`uncertain` follow-up delivery is monitored, never resent; a `RESPONSE_READY` record is completed without rereading; a `FAILED` record is a stable wait. `herdr-supervisor retry-answer` rereads the settled transcript once (only when the question may have been delivered), `return-to-decision` abandons the question and restores the decision without contacting any agent, and `revise` from that wait abandons it first and then applies to the restored decision. A session that no longer matches the recorded provider/native session fails closed before any contact; the decision stays returnable.

Prompt accounting (`prompt_metrics`) is written in the same durable record as each prepared delivery, so restart recovery reuses the record and never counts twice. The consecutive automatic-turn count (`consecutive_auto_turns`, limit `max_consecutive_auto_turns`) is changed only by accepted agent-to-agent routes and authenticated human continuations; polling, restart, resume, and reconciliation leave it untouched.

Alias loss is not session loss. Herdr can keep an exact native conversation while dropping its display alias (for example after logout/login). Every command target is resolved from owners.json: the alias is used only while it names the persisted session; otherwise the pane of the single live record with the persisted provider and exact native session id is used, without renaming, adopting, or replacing anything. Zero, multiple, identity-less, or changed-identity records fail closed; doctor distinguishes `exact_session_without_alias` (usable) from `missing`, `ambiguous`, `identity_unavailable`, and `identity_mismatch`. A missing session is restored only under the existing explicit restore policy.
